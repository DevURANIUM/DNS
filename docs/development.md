# Development and release

The production services use Python's standard library and distribution packages.
Build tools require Python 3; Bash is needed for installer syntax validation.

## Source layout

| Directory | Responsibility |
| --- | --- |
| `templates/services/` | Exit API/database, admin panel and relay sync/user panel |
| `templates/commands/` | Installed administration commands |
| `templates/config/` | nginx, nftables and coturn templates |
| `templates/systemd/` | Unit files and timers |
| `common/` | Shared DNS bypass, IPv6 filtering and kernel settings |
| `domains/` | Current catalogue and retained source snapshots |
| `assets/ui/` | Editable UI assets and licensed fonts |
| `tools/` | Build and static preview tools |

Repository layout does not change installed paths such as `/usr/local/bin/`
or `/etc/smart-dns/`. Do not move installed files to match this source tree.

## Build

```sh
python -B tools/build-installer.py
bash -n dns.sh
bash dns.sh --version
```

The builder embeds fonts, CSS and JavaScript in the two panel services, then
assembles every payload into `dns.sh`. The exit nginx HTTP map is generated by
`tools/route-map.py` from `domains/domains.txt`. The raw exit configuration has
a build placeholder and must not be copied directly into a running nginx.

Edit source templates and assets, not generated UI blocks or `dns.sh`.
The installer version is defined in `tools/installer-logic.sh`. Update the
README release number with it. Rebuilding identical sources should produce
identical installer bytes.

## Preview

```sh
python -B tools/preview-ui.py
python -m http.server 8765 --bind 127.0.0.1 --directory docs/preview
```

Open `http://127.0.0.1:8765/admin.html`, `users.html`, `user.html`,
`landing.html`, `user-login.html`, `login.html` or `signup.html`.
These pages use disposable sample accounts. Form submission is disabled.
Preview files, screenshots and Python caches are ignored and are not needed
for installation. Font attribution is in [the asset guide](../assets/ui/README.md).

## Release checks

- Parse Python services and build tools; run Bash syntax checks on shell commands.
- Build `dns.sh` and confirm every embedded payload is present and terminated.
- Check JSON catalogues and local documentation links.
- Generate previews to check that relocated service imports still work.
- Validate the rendered nginx configuration with `nginx -t` where available.
- On a staging pair, check fresh install, upgrade, account access and DNS rules.

Local build checks are not an end-to-end server or game connectivity test.
Publishing the repository and deploying the new installer are separate steps.
Update Exit before Relay when catalogue or routing rules change.

It preserves the 0.3.35 routing behavior and installed command names. Obsolete
