# DNS

پنل و زیرساخت Smart DNS برای مدیریت دسترسی به سرویس‌ها، کاربران و مصرف ترافیک؛ با معماری رله و سرور خروجی.

[مخزن پروژه](https://github.com/DevURANIUM/DNS) · [گزارش مشکل](https://github.com/DevURANIUM/DNS/issues) · [English](README.md)

## معرفی

DNS درخواست دامنه‌های انتخاب‌شده را از طریق یک رله به سرور خروجی منتقل می‌کند. دامنه‌های دیگر به‌صورت عادی پاسخ داده می‌شوند. پنل مدیریت روی سرور خروجی و پنل کاربران روی رله اجرا می‌شوند؛ اطلاعات حساب‌ها و مصرف در یک پایگاه داده مرکزی نگهداری می‌شود.

```text
کاربر ← DNS → رله داخل ایران → سرور خروجی → سرویس مقصد
                   ↓                ↑
              پنل کاربر       پنل مدیریت و پایگاه داده
                   └── همگام‌سازی هر ۳۰ ثانیه ──┘
```

پروکسی HTTPS با خواندن SNI مسیر را مشخص می‌کند و محتوای TLS را رمزگشایی نمی‌کند. این پروژه VPN عمومی نیست؛ مسیر دامنه‌های تعریف‌شده را مدیریت می‌کند.

## امکانات

| بخش | قابلیت‌ها |
| --- | --- |
| پنل مدیریت | مدیریت کاربران، سهمیه، سرعت دانلود، زمان اعتبار، قالب سرویس و دامنه‌ها |
| پنل کاربر | ثبت‌نام، ورود، ثبت آی‌پی، مشاهده مصرف، تغییر رمز و ارسال رسید پرداخت |
| رابط کاربری | فارسی و راست‌به‌چپ، سازگار با موبایل، فونت محلی وزیرمتن، تم روشن و تاریک |
| ابزارهای پنل | جست‌وجوی فارسی در جدول‌ها، فیلتر وضعیت، شمارنده نتایج و فهرست موارد نیازمند بررسی |
| راه‌اندازی اتصال | کپی آدرس DNS و راهنمای اتصال و رفع مشکل در پنل کاربر |
| کنترل دسترسی | فهرست آی‌پی مجاز، شمارش ترافیک با nftables و قطع دسترسی پس از پایان سهمیه یا اعتبار |
| پلن‌ها | سهمیه ماهانه یا یک‌باره، محدودیت سرعت دانلود و انتخاب سرویس‌ها برای هر قالب |
| نگهداری | مانیتورینگ سرورها، لاگ، بکاپ و بازیابی، دریافت و تمدید گواهی TLS |

فونت و فایل‌های رابط کاربری داخل خروجی نصب قرار می‌گیرند؛ نمایش پنل‌ها به CDN وابسته نیست. ثبت‌نام به‌تنهایی سرویس را فعال نمی‌کند؛ مدیر باید برای حساب پلن ذخیره کند. پرداخت‌ها با ارسال رسید و بررسی دستی مدیریت می‌شوند.

## پیش‌نیازها

- دو سرور Debian یا Ubuntu با آی‌پی عمومی: یک رله داخل ایران و یک سرور خروجی خارج از ایران.
- دسترسی مدیریتی `sudo` یا `root` روی سرورها.
- ارتباط شبکه مناسب بین رله و خروجی و دسترسی به مخازن بسته‌های سیستم‌عامل.
- برای پنل HTTPS، دامنه‌ای که به سرور مربوط اشاره کند و گواهی معتبر داشته باشد. دریافت خودکار گواهی از طریق HTTP به دسترسی پورت ۸۰ نیاز دارد.

نصب‌کننده بسته‌های لازم، از جمله nginx، dnsmasq، nftables و Python را از سیستم‌عامل نصب می‌کند. سرویس به npm، pip یا Docker نیاز ندارد.

## نصب

ابتدا **سرور خروجی** و سپس **رله** را نصب کنید. روی هر سرور:

```sh
curl -fsSLO https://raw.githubusercontent.com/DevURANIUM/DNS/main/dns.sh && sudo bash dns.sh
```

نصب‌کننده نقش سرور و تنظیمات موردنیاز را می‌پرسد. توکن دریافتی از نصب خروجی را هنگام نصب رله وارد کنید. در پایان، اطلاعات اتصال و آدرس پنل‌های فعال نمایش داده می‌شود.

فایل را ابتدا دانلود کنید و سپس اجرا کنید؛ نصب‌کننده داده‌های لازم را از خود فایل می‌خواند و برای اجرای مستقیم با پایپ طراحی نشده است. نام فایل نصب `dns.sh` است.

### پورت‌ها

| پورت | رله | خروجی |
| --- | --- | --- |
| 53 TCP/UDP | DNS کاربران | — |
| 80 TCP | ترافیک HTTP و اعتبارسنجی گواهی | ترافیک HTTP و اعتبارسنجی گواهی |
| 443 TCP | پروکسی SNI | پروکسی SNI |
| 3478 UDP | STUN | — |
| 8443 TCP | پنل کاربر با TLS | API همگام‌سازی |
| 9443 TCP، پیش‌فرض | — | پنل مدیریت؛ قابل تغییر |
| 22 TCP | SSH | SSH |

پورت 8446 در خروجی برای مسیر محلی Google روی IPv6 استفاده می‌شود و نیازی به بازکردن عمومی ندارد. دسترسی پورت‌ها را در فایروال سیستم و پنل ارائه‌دهنده سرور مطابق نقش هر ماشین تنظیم کنید.

### اولین اتصال

1. در پنل کاربر حساب بسازید.
2. مدیر از بخش کاربران، سهمیه و اعتبار پلن را ذخیره کند.
3. با همان اینترنت دستگاه موردنظر وارد پنل شوید و آی‌پی را ثبت کنید.
4. DNS نمایش‌داده‌شده را در تنظیمات شبکه وارد کنید. اگر DNS دوم لازم است، همان آدرس را تکرار کنید.
5. پس از تغییر اینترنت یا آی‌پی مودم، آی‌پی را دوباره در پنل ثبت کنید.

رله تازه‌نصب‌شده ابتدا باز است و پس از اولین همگام‌سازی دارای آدرس ثبت‌شده، کنترل دسترسی خودکار فعال می‌شود. وضعیت را با `sudo smartdns-acl enforce status` بررسی کنید. SSH تحت این محدودیت قرار نمی‌گیرد.

## به‌روزرسانی و حذف

برای به‌روزرسانی، فایل جدید را از دستور نصب دانلود و دوباره اجرا کنید. نصب‌کننده نسخه را بررسی می‌کند و پیش از ادامه تأیید می‌گیرد. تنظیمات و داده‌های کاربران حفظ می‌شوند و از پایگاه داده در `/var/backups/smart-dns/` بکاپ گرفته می‌شود.

```sh
# نمایش نسخه، بدون نصب
bash dns.sh --version

# حذف سرویس از همین سرور
sudo bash dns.sh --uninstall
```

## فرمان‌های کاربردی

```sh
# روی خروجی: نمایش آدرس پنل مدیریت
sudo smartdns-access

# روی رله: بررسی سرویس و قوانین دامنه
sudo smartdns status
sudo smartdns list
sudo smartdns find spotify
sudo smartdns-rules check example.com
sudo smartdns-acl enforce status

# روی هر دو سرور: عیب‌یابی و راه‌اندازی مجدد
sudo smartdns-logs -e
sudo smartdns-logs -f
sudo smartdns-logs --report
sudo smartdns-restart
```

گزارش خروجی اطلاعات محرمانه تنظیمات را ماسک می‌کند، اما می‌تواند شامل آی‌پی و نام کاربران باشد؛ پیش از انتشار آن را بررسی کنید. راه‌اندازی مجدد ممکن است اتصال‌های جاری را موقتاً قطع کند.

## توسعه و پیش‌نمایش

| مسیر | کاربرد |
| --- | --- |
| `templates/` | سرویس‌های Python، ابزارهای مدیریتی و تنظیمات سرویس‌ها |
| `tools/installer-logic.sh` | منطق نصب و به‌روزرسانی |
| `assets/ui/` | CSS، JavaScript، فونت و مجوز فونت |
| `domains/` | فهرست دامنه‌ها و دسته‌بندی سرویس‌ها |
| `common/` | تنظیمات مشترک شبکه |
| `tools/` | ساخت خروجی، پیش‌نمایش و تست‌ها |

```sh
# ساخت پنل‌ها و فایل نصب از منابع
python tools/build-installer.py
bash -n dns.sh

# تست اعتبارسنجی فرم و حفظ سهمیه اعشاری
python tools/test-ui-regressions.py

# تولید پیش‌نمایش با داده نمونه
python tools/preview-ui.py
python -m http.server 8765 --bind 127.0.0.1 --directory docs/preview
```

پس از اجرای سرور محلی، [پنل مدیریت](http://127.0.0.1:8765/admin.html)، [کاربران](http://127.0.0.1:8765/users.html) و [پنل کاربر](http://127.0.0.1:8765/user.html) قابل مشاهده‌اند. پیش‌نمایش‌ها ثابت هستند و عملیات واقعی سرور را اجرا نمی‌کنند.

فایل نصب و بلوک‌های رابط کاربری داخل قالب‌ها تولیدشده‌اند؛ تغییرات را در منابع انجام دهید و دوباره بسازید. [جزئیات تغییرات رابط کاربری](docs/UI-update.fa.md) و [راهنمای فایل‌های UI](assets/ui/README.md) در دسترس‌اند.

## محدودیت‌ها و گزارش مشکل

پروژه در مرحله آلفا است. کیفیت اتصال به مسیر شبکه، ارائه‌دهنده و سرویس مقصد وابسته است. محدودیت سرعت فقط برای دانلود اعمال می‌شود؛ پنل کاربر بدون گواهی TLS ارائه نمی‌شود. توقف دانلود Xbox از محدودیت‌های گزارش‌شده قبلی است و رفع آن در این نسخه تأیید نشده است.

برای گزارش باگ، در [Issues مخزن DNS](https://github.com/DevURANIUM/DNS/issues) نقش سرور، سیستم‌عامل، نسخه، مراحل بازتولید و خروجی مرتبط را بنویسید. رمز عبور، توکن و آدرس خصوصی پنل مدیریت را منتشر نکنید.
